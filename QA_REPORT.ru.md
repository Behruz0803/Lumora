| База | SQLite (dev-вариант), модели совместимы с PostgreSQL |
| Фронтенд | React 18.3, Vite 5.4.21, TypeScript 5.6, Tailwind 3.4, Recharts 2.15, React Router 6.30 |
| API-сервер | `uvicorn app.main:app --host 0.0.0.0 --port 8000` (демо-данные автоматом) |
| Веб-сервер | `vite --host 0.0.0.0 --port 5173`, прокси `/api` → `127.0.0.1:8000` |
| UI-тесты | Vitest + jsdom + Testing Library, фикстуры **записаны с живого бэкенда** |

**Почему DOM-тесты:** песочница блокирует загрузку браузерных бинарников (CDN Playwright/Chromium
недоступен), поэтому реальная браузерная автоматизация была невозможна. Вместо неё каждый тест
рендерит настоящее React-приложение, выполняет реальные действия пользователя и получает
**дословные ответы работающего FastAPI**, то есть контракты проверяются end-to-end. Ограничения — в §10.

## 4. Проверка Killer Flow (спецификация §4)

Сценарий: владельцу магазина Дилшоду нужно **100 кг картофеля**.

| Шаг | Требование | Проверенное поведение | Статус |
| --- | --- | --- | --- |
| 1 | Открывает PriceRadar | `/` требует auth; демо-вход `dilshod@priceradar.uz / demo1234` ведёт на панель | ✅ |
| 2 | Ищет картофель | Поиск возвращает ровно 1 результат | ✅ |
| 3 | Вводит 100 кг | Поле по умолчанию 100 для кг/л, пресеты 25/50/100/250, живой пересчёт | ✅ |
| 4 | Видит предложения поставщиков | 4 предложения: A 450 000, B 400 000, C 420 000 UZS (точные значения спецификации) | ✅ |
| 5 | Движок рекомендует поставщика B | `recommended.supplier_name = Fergana Fresh Produce`, `total_cost = 400 000`, `rank = 1` | ✅ |
| 6 | Понятное сравнение и причина | Пояснение: B на 20 000 дешевле следующего, C с бесплатной доставкой 420 000, A 450 000 и почему исключён самый низкий юнит-цена (3 300, нет в наличии) | ✅ |
| 7 | Нажимает «Связаться с поставщиком» | Модалка: поставщик, телефон `+998 73 244 18 65`, город, условия доставки, копируемый заказ, ссылка `tel:` | ✅ |
| 8 | Сводка заказа и экономия против A | 350 000 + 50 000 = 400 000; экономия **50 000 UZS** против A; 4 000 за доставленный кг | ✅ |

Дополнительно:

* Поставщик из Намангана без наличия (юнит-цена 3 300 — минимальная на рынке) **никогда не
  ранжируется**, причина «Сейчас нет в наличии».
* 25 кг → подходит только Бухара (минимум 20 кг, бесплатная доставка) → 105 000 UZS.
* 10 кг → никто не может выполнить → явное пустое состояние, без падения.
* 5 000 кг → больше всех запасов → без рекомендации, понятное объяснение.
* Ровно минимальный заказ (20 кг) → подходит (граница корректна).
* Для каждого подходящего предложения `total_cost == unit_price × 100 + delivery_cost`.

Одним запросом:

```bash
curl -X POST http://localhost:8000/api/recommendations/compare \
  -H "Content-Type: application/json" -d '{"product_id": 1, "quantity": 100}'
```

## 5. Журнал дефектов — найдено и исправлено

Все пункты исправлены в этой сессии, каждый фикс покрыт регрессионным тестом, полные наборы
перезапущены после исправлений.

### 5.1 Проход 1 — функциональные дефекты

| ID | Важность | Область | Дефект | Исправление |
| --- | --- | --- | --- | --- |
| D-01 | **Серьёзный** | Движок рекомендаций | Пояснение сравнивало только со *следующим* дешёвым предложением и не сообщало экономию против самого дорогого подходящего (шаг 8 спецификации не выполнялся текстом) | `explain()` теперь перечисляет все остальные подходящие варианты с суммами и добавляет явное «выбор X экономит 50 000 UZS» |
| D-02 | **Серьёзный** | Контракт API | В ответе не было `updated_at`, колонка «последнее обновление» показывала прочерк | `updated_at` добавлен в `ScoredOffer`/`OfferInput`; таблица и мобильные карточки показывают относительное время |
| D-03 | **Серьёзный** | Карточка товара | Предложения всегда считались на 100 единиц, поэтому «лотковые» товары (яйца) показывали неверные суммы против метки 10 лотков | Эталонное количество берётся из единицы товара (100 кг/л, 10 лотков) |
| D-04 | **Серьёзный** | Навигация | Диплинк из профиля поставщика `/products?category=Vegetables` игнорировался каталогом | Категория инициализируется из URL и синхронизируется с ним |
| D-05 | **Серьёзный** | Стили | `h-4.5`/`w-4.5` (нет в Tailwind) использовались 24 раза — размеры иконок молча терялись | Добавлен `spacing['4.5']`, наличие класса проверено в собранном CSS |
| D-06 | **Серьёзный** | Аналитика | `active_suppliers`/`total_offers` в `/analytics/overview` считались по остаточной заглушке | Заменено на `count(distinct(supplier_id))` и `count(offers)` |
| D-07 | Незначительный | Аналитика | Серии поставщиков в истории цен брали id первой строки | Серии явно связывают offer → supplier id/имя |
| D-08 | Незначительный | Производительность | Диплинк `/compare?product=1&qty=100` отправлял один и тот же запрос дважды | Защита по ключу последнего запроса (ручной пересчёт принудительный) |
| D-09 | Незначительный | Чистота UI | Скрытая фиктивная кнопка в заголовке, пустая ячейка «последнее обновление», лишний пустой `<PageHeader>` | Удалено; фиктивное действие заменено рабочей кнопкой «Загрузить пример 100 кг картофеля» |
| D-10 | Незначительный | Аналитика | Запрос спроса дважды джойнил товары и игнорировал наличие по категории | Переписан в один сгруппированный запрос |
| D-11 | Незначительный | Ассистент | В обработчике тренда была недостижимая логика, способная дать неверные числа | Удалена; окно считается от самой новой точки |
| D-12 | Незначительный | Упаковка бэкенда | Список реэкспортов `app.schemas` устарел и ломал импорт новых схем | Переведено на wildcard-реэкспорт |
| D-13 | Незначительный | UX | Повторное сохранение предложения давало общую ошибку | 409 теперь сообщает «уже сохранено», кнопка синхронизируется в «Сохранено» |

### 5.2 Проход 2 — adversarial и ошибочные пути

| ID | Важность | Область | Дефект | Исправление |
| --- | --- | --- | --- | --- |
| D-14 | **Серьёзный** | Обработка ошибок API | Любой запрос, отклонённый **кастомным** валидатором Pydantic, давал **HTTP 500 и обрыв соединения** (объект `ValueError` не сериализуется в JSON) | Добавлен `_json_safe_errors()`: `type`/`loc`/`msg`/`input`/`ctx` приводятся к JSON-безопасным значениям |
| D-15 | **Серьёзный** | Обработка ошибок API | `{"quantity": 1e400}` или `NaN` давали тот же 500 (`allow_nan=False`) | `_json_safe()` превращает нефинитные float в строки на любой глубине |
| D-16 | **Серьёзный** | Auth / сессия | Если `/auth/me` падал по любой причине (сервер недоступен, сеть, 500), токен стирался и пользователя выбрасывало на `/login` | Сессию завершает только **401**; остальные ошибки сохраняют токен и показывают `ConnectionErrorScreen` с «Повторить» / «Выйти» |
| D-17 | **Серьёзный** | Навигация | Страница сравнения читала `?product=`/`?search=` один раз при монтировании; поиск в шапке на `/compare` менял URL, но страница оставалась прежней | Эффект диплинка привязан к параметрам URL; неверный id показывает ошибку |
| D-18 | Незначительный | Ассистент | Сообщение из одних пробелов принималось (200) и отвечало общим текстом помощи | Валидатор `AssistantRequest.message` отклоняет пустой ввод (422) |
| D-19 | Незначительный | Сохранённые предложения | Очистка поля количества считала суммы при количестве 0, и таблица показывала только доставку (50 000 UZS) как реальную сумму | При неверном количестве суммы скрыты, показывается «Введите количество больше нуля», `aria-invalid` |
| D-20 | Незначительный | Инструменты | `npm run preview` отдавал сборку **без** прокси `/api`; в `package.json` не было скрипта `test` | Прокси добавлен, добавлены `test` / `test:watch` |

### 5.3 Проход 3 — поддержка языков (English · O‘zbekcha · Русский)

Требование: интерфейс должен **реально переключаться** на каждый из трёх языков — и в приложении,
и в подготовленных материалах. По пути найдено и исправлено 6 дефектов локализации.

| ID | Важность | Область | Дефект | Исправление | Регрессионный тест |
| --- | --- | --- | --- | --- | --- |
| D-21 | **Серьёзный** | Смена языка | Выбор языка менял сохранённую настройку и подпись переключателя, но открытые страницы оставались на прежнем языке — корень React был смонтирован один раз | `App` стал подписчиком `useSyncExternalStore` и рендерит `<AppShell key={language} />`, поэтому все экраны перемонтируются на новом языке | `i18n.test.tsx::switching language re-renders the whole app` |
| D-22 | **Серьёзный** | Серверный текст | Пояснения рекомендаций, причины отказа и все ответы ассистента формировались только по-английски | `backend/app/core/i18n.py` хранит шаблоны; `pricing.py`/`assistant.py` принимают `language`; эндпоинты определяют её из `Accept-Language` (или `?lang=`); `services/api.ts` отправляет заголовок с каждым запросом | `tests/test_i18n.py` (26 тестов) |
| D-23 | **Серьёзный** | Демо-названия в тексте | Названия товаров, категории, единицы и города внутри предложений оставались английскими («100 kg of **Potatoes**») | Добавлены `DATA_NAMES`/`localise()`; плейсхолдеры получают локализованные названия и единицы (кг/л, шт/лоток) | `test_i18n.py` + живая curl-матрица |
| D-24 | Незначительный | Качество перевода | Русские предложения читались плохо («Для «Potatoes» на 100 kg») | Переписаны пять шаблонов: «Для заказа «…»», «Ни один поставщик не может выполнить заказ…», «Варианты поставщиков по товару «…»» | Ручная проверка матрицы en/ru/uz |
| D-25 | Незначительный | Поломка сборки | Дубли ключей в `locales/uz/ui.ts` и `ru/ui.ts` ломали `tsc` с `TS1117` | Дедупликация скриптом с учётом многострочных записей, одна пара удалена вручную | `npm run typecheck` чистый, Vitest зелёный |
| D-26 | Незначительный | Покрытие | Тест покрытия словаря не ловил частично переведённые строки | Тест сверяет каждый ключ `tr()` с обоими словарями, ведёт явный список «одинаковых по смыслу» строк и проверяет сохранность плейсхолдеров | `i18n.test.tsx` (19 тестов) |

Матрица локализации (живой API):

| Язык | Пояснение сравнения | Причина отказа | Ответ ассистента |
| --- | --- | --- | --- |
| `en` | “Recommended: Fergana Fresh Produce — 100 kg x 3 500 UZS … 400 000 UZS total” | “Currently out of stock” | “For 100 kg of Potatoes, the lowest total cost is 400 000 UZS …” |
| `ru` | “Рекомендуется: Fergana Fresh Produce — 100 кг × 3 500 UZS … итого 400 000 UZS” | “Сейчас нет в наличии” | “Для заказа «Картофель» на 100 кг наименьшая общая стоимость — 400 000 UZS …” |
| `uz` | “Tavsiya etiladi: Fergana Fresh Produce — 100 kg x 3 500 UZS … jami 400 000 UZS” | “Hozir omborda yo‘q” | “Kartoshka mahsulotidan 100 kg uchun eng past umumiy xarajat — 400 000 UZS …” |
| `fr-FR` (не поддерживается) | Английский fallback, HTTP 200 | Английский | Английский |
| `?lang=uz` + `Accept-Language: ru` | Побеждает параметр (узбекский) | Узбекский | Узбекский |

Покрытие интерфейса в `frontend/src/test/i18n.test.tsx`:

* Собираются **476 ключей UI**, каждый присутствует в `uz` и `ru` (**476/476**).
* Молчаливого fallback нет: пропущенный ключ, оставшийся английский текст или потерянный
  `{placeholder}` валит набор.
* Переключение `en → uz → ru → en` через настоящий переключатель перерисовывает страницы, меню,
  таблицы, графики и экран ассистента; выбор сохраняется после перезагрузки (`localStorage`) и
  записывается в аккаунт.
* Склонения: в русском `one/few/many`, в узбекском одна форма, в английском `one/other`; валюта UZS
  с группировкой пробелами.
* Проверяется, что API-клиент отправляет `Accept-Language` активного языка с **каждым** запросом
  (`i18n.test.tsx::API language header`), поэтому интерфейс и серверный текст не расходятся.

### 5.4 Проблемы тестового инструментария (не дефекты продукта)

Устаревшие фикстуры до D-01/D-02, неоднозначные матчеры текста, stub буфера обмена, конфликтующий с
`user-event`, и повторные `409` при перезапуске probe-скрипта. Всё устранено: фикстуры
перезаписываются с живого API, probe-скрипт использует уникальные email/телефон для каждого запуска.

## 9. Корректность стоимости и рекомендаций

* Формула реализована один раз в `app/services/pricing.py` и продублирована в фронтенде только для
  мгновенного превью.
* Деньги — целые UZS; одно округление половины вверх на `unit_price × quantity`.
* Валидация ввода: цена > 0, количество > 0, доставка ≥ 0 → `PricingError` → HTTP 422.
* Инварианты проверены по 8 товарам × количествам (1; 7,5; 25; 100; 250):
  `total_cost == round(unit_price × qty) + delivery_cost`; неподходящие/отсутствующие предложения
  не ранжируются.
* Рейтинг по полной стоимости, детерминированный tie-break (рейтинг, затем id) — стабилен между вызовами.
* «Лучшее в целом» может отличаться от «самого дешёвого» из-за оценки качества/доставки; UI показывает
  это как явную альтернативу с наценкой.
* Зависимость от количества проверена: при 50 кг выигрывает дорогой/бесплатная доставка, при 1 000 кг —
  дешёвый/дорогая доставка.
* Защита от ловушки: при 100 кг предложение 4 200 с бесплатной доставкой выгоднее 4 000 + 50 000 доставки.

## 10. Что не покрыто / ограничения

1. **Нет автоматизации в реальном браузере** (загрузка Chromium заблокирована): нет скриншотов,
   кросс-браузерных прогонов (Firefox/Safari/WebKit), Lighthouse-метрик и настоящего рендеринга вьюпорта.
2. **Docker compose не запускался** — в песочнице нет Docker daemon. Файлы согласованы, но нужен
   один smoke-прогон на машине с Docker.
3. **Режим PostgreSQL не запускался** — только SQLite. Модели совместимы, но перед продом нужен один
   интеграционный прогон.
4. **Пентеста нет** — JWT/bcrypt/CORS/валидация проверены ревью и негативными тестами, но фаззинга,
   rate-limit и сканирования CVE не было.
5. **Нагрузочного тестирования нет.**
6. Демо-области по дизайну: уведомления сохраняются, но не отправляются; *названия компаний*
   поставщиков остаются как есть во всех языках; ассистент — движок на правилах без внешней модели.
   Он понимает узбекские/русские вопросы по ключевым словам, но ключевые слова основаны на английских
   формулировках, поэтому чисто узбекская фраза получит текст помощи на выбранном языке, а не
   разобранный интент.
7. **Качество перевода** проверено чтением матрицы en/uz/ru и 476 ключей UI, но профессиональной
   лингвистической подписи нет.

## 11. Как воспроизвести всё

```bash
# 1. Бэкенд: unit + интеграционные
cd backend && python -m pytest tests -q                     # 159 passed (26 тестов локализации)

# 2. Одноразовый API для живых наборов (демо-база остаётся чистой)
cd backend && rm -f qa_smoke.db && \
  DATABASE_URL=sqlite:///./qa_smoke.db uvicorn app.main:app --port 8001

# 3. Живой smoke-набор API
python scripts/qa_smoke.py http://127.0.0.1:8001             # 110/110 passed

# 4. Adversarial-пробы
python scripts/qa_edge_probes.py http://127.0.0.1:8001       # 57/57 passed

# 5. Фронтенд
cd frontend
npm run typecheck                                           # clean
npm test                                                    # 117 passed (19 i18n)
npm run build                                               # success
npm run preview                                             # :4173 + прокси /api

# 6. Языковая матрица (нужен запущенный API)
for L in en ru uz; do
  curl -s -X POST http://127.0.0.1:8000/api/recommendations/compare \
    -H "Content-Type: application/json" -H "Accept-Language: $L" \
    -d '{"product_id": 1, "quantity": 100}' | head -c 200; echo
done
```

Оба QA-скрипта создают демо-пользователей и предложения, поэтому всегда запускайте их против одноразовой
базы (`qa_smoke.db` / `qa_probe.db`) и удаляйте файл после — демонстрационная база должна оставаться чистой.
